# 0007 预览右栏顶对齐、不画标头

> 宽度部分由 [0008](0008-fixed-left-column-width.md) 取代：现在按整题内容一次定宽，不再按可见行收紧。

## 决定

- preview 不画 `Preview` 标头，正文直接起。
- 并排时右栏从 Tab / 题干那一行开始，与左栏顶部对齐；右栏比左栏多出的行不把面板撑高，面板高度仍只由 `ui.maxHeightRatio` 预算封顶。
- 左栏宽先封顶 `min(floor(width × 0.42), 54)`（并给右栏留 ≥ 12 列），封顶内再按左侧实际内容最大宽度收紧，省下的列给右栏。
- 裁剪仍按 [0004](0004-side-by-side-trim.md)：两栏各自独立裁，互不补偿。

## 为什么

- 标头那行没有信息量：用户已经在题干和预览正文里看懂这块是预览，省下的一行直接给内容。
- 右栏等选项区才起排，会把整个面板往下撑高。面板一高就挤掉聊天区，而预览本来就是宽屏才有资格出现的内容，不该反过来压缩对话。
- 左栏按 42% 固定宽，短选项时会留一大片空白，竖线离正文太远；按内容收紧能把列让给预览。

## 代价

- 竖线位置随当前最长左行变化，焦点换到更短的选项时会左移几格，视觉上不如固定列稳。
- 左栏收到 12 列下限时，长 label 会被 `…` 截得更早；要看全文得靠 `detail` 与预览。
- 右栏能用的行数含 Tab / 题干那几行，和左栏 body 的行数不再一一对应；算高度时不能假设两栏起点相同。
