# 0064 存活按 agent 缺席三次判定

有回合在飞的 run，每 15 秒查一次 `herdr agent list`。连续三次查不到该 agent，判定失去联系，投 `lost`。pane 不在 `pane list` 里则立即判定。

空闲 run 不查。它没有在跑的东西，也没有需要报的结果。

## 为什么

`agent_settled` 一定写回合事件（DEC-0062）。正常结束、失败、中断都有事件。唯一没有事件的是进程被强杀。这时 pane 还在，只有 agent 登记会消失。

旧实现 10 秒判死，依据是登记抖动实测超过 4 秒。单次抖动就会误杀。三次 15 秒把窗口拉到 45 秒，代价是强杀最晚 45 秒才报出。

## 代价

- 工作的子代理每 15 秒一次 `agent list`，一天 5760 次。旧实现每秒一次，86400 次。
- 强杀的最坏发现时间是 45 秒。
- 不用 herdr socket：CLI 没有订阅命令，protocol 22 没有 pane 关闭事件，Node 连 `HERDR_SOCKET_PATH` 报 `ENOTSOCK`（DEC-0052）。

## 否决的替代

- 单次缺席就判死。就是 2026-11 那次误杀的原因。
- 读 pane 文本判断死活。文本不稳定，也没有契约。
- 父代理不问，等下一次 `send` 才发现。父代理永远收不到结果。
