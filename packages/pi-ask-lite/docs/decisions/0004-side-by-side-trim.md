# 0004 并排时两栏独立裁剪

## 决定

左右并排（终端宽 ≥ `ui.preview.minSideBySideWidth`）时，左栏与右栏各自按同一高度预算裁：左栏先丢 detail 行再收选项窗口，右栏只留预算内的 preview 行，两栏互不补偿。上下堆叠时仍按 preview 行 → detail 行 → 选项窗口。

## 为什么

- 两栏共用同一高度预算，右栏少画一行并不能让左栏多画一行：左栏的行数只由左栏自己的内容决定。把两栏当成一条统一裁剪序列，并排时「先裁 preview」只会让右栏先空掉，左栏的 detail 却原样留着，屏幕更空。
- 左栏是必读内容（选项与 detail），右栏是辅助内容（preview），各自按自身优先级裁更稳：宽屏不会因为 preview 长就先丢 detail，也不会因为 detail 多就整块吞掉 preview。
- 堆叠时两者抢同一列，才需要一个统一顺序：preview 行 → detail 行 → 选项窗口。

## 代价

- 两种布局两套规则，spec 与测试必须分别写清；改代码前先看这条。
- 并排时右栏可能比左栏矮，横向留白比统一序列多一两行；宽屏下可接受。
- 以后若想让「右栏让位抬高左栏」，等于推翻这条，需要新开一条注明取代本档。
