# 0014 spill 落到 agent 目录，按会话分层并保留 7 天

`context.spillToFile` 为真时，全文写到 `<agent dir>/pi-web-search-lite/spill/<session id>/<tool>-<timestamp>.md`。同一会话同一毫秒重复写时文件名加序号，不覆盖已回填的路径。扩展加载时删掉 spill 根下超过 7 天没动过的会话目录，只删目录、不碰散文件。写盘失败不抛错：照常返回截断内容，用一行写明没写成。

为什么：

1. 系统临时目录既不保证留存，也容易被当成可随手删的垃圾；路径已经进了会话记录，模型之后还要 `read`。放到与 `config.json` 同一个 agent 目录下，路径可预期，跟着 `PI_CODING_AGENT_DIR` 走。
2. 按会话分目录：多个 pi 会话并行时互不覆盖，清理也能整块删。
3. 7 天保留期比「随进程退出删」宽松：会话可以关掉再回来读；又比「永不删」收敛，长期使用不会无限涨。
4. 写盘失败降级而不是抛错：抓取结果还在，没必要因为写不了文件丢掉整页。

不做的：spill 目录可配（YAGNI）、跨会话共享一份正文（会互相覆盖）、按大小配额（先看保留期够不够）。旧版本写在系统临时目录，那些目录不由扩展删除，留给用户。
