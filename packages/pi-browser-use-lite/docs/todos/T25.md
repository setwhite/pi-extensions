# T25 扩展动作接线

- [ ] 未开始

## 交付物

`browser-extension/background/dispatch.js` 的 24 个动作接上实现。每个动作一行，把活交给已有模块：`tabs.js`、`page/`、`input/`、`target.js`。

另有两点不散进 24 个 handler：

1. target 解析在 dispatch 前置一步：`params.tabId ?? await targetFor({ sessionKey, action })`。
2. 交互类动作的 `changed` 在 dispatch 后置一步：动作前拍一次基线（`snapshotPage` 的 `changes` 模式），动作后比对一次，把 `{ added, removed, updated }` 并进结果。比对复用 `snapshot.js` 的实现，不另写 diff。

wire 契约（宿主发什么、扩展回什么）见 [modules/exec.md](../modules/exec.md)。

## 验收

- AC1：`pnpm --filter pi-browser-use-lite test extension/dispatch` 通过。
- AC2：`routes` 里没有 `undefined` 值，且键集合与 `src/protocol` 的 `ACTION_NAMES` 双向相等。
- AC3：不带 `tabId` 时先按 `targetFor({ sessionKey, action })` 取 target；带 `tabId` 时不调 `targetFor`，也不建标签。
- AC4：参数按 wire 表逐个转发。宿主已发 camelCase（`initScript`、`timeoutMs`、`fullPage`、`requestId`、`maxElements`、`textChars`、`groupName`、`groupColor`），dispatch 不改名。
- AC5：交互类动作（click、type、fill、key、drag、scroll、upload）的结果带 `changed: { added, removed, updated }`，其余动作不带。
- AC6：抛错只抛 `<class>: message`，不包 `{ ok: false }`（信封归 `transport.js`，分类归宿主的 `classify()`）。
- AC7：`automation.cleanup` 走 `cleanupAutomation({ sessionKey, closeOwnTabs })`。
- AC8：`tab.new` 走 `createTarget` 写台账；随后同一会话的 `page.snapshot` 不再建标签。
- AC9：`cdp.call` 走 `input/debugger.js` 的 `sendCommand`；没权限时 `cdp_unavailable` 原样抛，不吞。
