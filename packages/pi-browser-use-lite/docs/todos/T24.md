# T24 console 与 network 捕获

- [~] 待审

## 交付物

`background/capture.js`：`webNavigation.onCommitted` 时挂调试器、开 `Runtime` 与 `Network` 两个域，从导航起抓 `console` 与 `network`，缓冲区在后台按标签各存一份。`chrome_see` 的 `logs`、`request_id`、`clear` 走这里。契约见 [SPEC-0001](../specs/0001-tool-surface.md) 的 `chrome_see` 段。

## 验收

- AC1：`pnpm --filter pi-browser-use-lite test extension/capture` 通过。
- AC2：导航后立刻执行的页面脚本产生的 `console` 条目被记到，不需要先手动点一下。
- AC3：`console` 条目超过 500 条时丢最旧的，总数停在 500。
- AC4：`network` 记的请求含方法、URL、状态、耗时；请求体超过 200,000 字符时被截断并注明。
- AC5：同一标签页再导航一次后，`logs: "network"` 仍能返回上一次导航期间的请求。
- AC6：`clear: true` 后同类日志为空；另一种日志不受影响。
- AC7：`request_id` 取已知请求返回详情；取未知 id 抛 `bad_args`。
- AC8：挂不上调试器时不阻塞导航，`logs` 的头部含一行说明抓取未启用的提示。
- AC9：`background/index.js` 注册了 `chrome.webNavigation.onCommitted` 监听，且该权限来自 manifest。
- AC10：`page.console.list`、`page.network.list`、`page.network.get` 接进 `dispatch.js` 的路由表，三条的 `… is not wired yet` 消失。
