# T20 目标隔离与清理

- [x] 已完成（2026-11-08 审计后修复）

## 交付物

扩展侧 `background/target.js`：每个 sessionKey 独立自动化 target。所有权落 `storage.session` 与 `storage.local`。清理只关本会话创建的标签。

## 验收

- AC1：`pnpm --filter pi-browser-use-lite test policy/target` 通过。
- AC2：两个不同的 sessionKey 得到不同 target。
- AC3：清理其中一个，另一个的 target 仍在。
- AC4：`automation.cleanup` 只关本会话创建的标签，不关用户自己加进组里的标签。
- AC5：重新加载扩展后，能从未被清空的存储里读回本会话的 target。
- AC6：用户关掉自动化 target 的标签页后，`chrome_see` 返回 `no_target`，不静默新建 target；随后的 `chrome_act navigate` 能建出新 target。
- AC7：`cleanupAutomation` 在 `closeOwnTabs` 为 `true` 时关掉本会话创建的标签，为 `false` 时只清台账、标签保留。读 `policy.closeOwnTabsOnExit` 与会话结束时的调用点在 T23。
- AC8：`tab.activate`、`tab.group`、`tab.close`、`cdp.call` 取 target 时不会建新的——按动作名判断，只有 `page.navigate` 会建；断言这四个动作的桩里没有创建或激活 target 的调用，已有 target 时返回它。
