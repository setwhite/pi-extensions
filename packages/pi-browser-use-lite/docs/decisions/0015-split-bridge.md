# 0015 拆 bridge

## 问题

`src/bridge/index.ts` 一个类扛六组职责：命令队列、waiter 唤醒、端口选举、抢端口、超时、版本闸。它是全包唯一有真并发的地方，正确性只能靠通读。

## 选项

1. 不拆，靠测试兜。现有测试全用真端口，端口选举与抢端口的分支测不全。
2. 按端点拆（`server/next.ts`、`server/result.ts`）。状态被切散：一条命令的生命周期横跨入队、投递、回传，按端点切等于让三处各持一半。
3. 按职责拆成门面 + 三个文件。

## 选了

3。方案与迁移步骤见 [RFC-0001](../rfc/0001-split-bridge.md)，这里只记结论。

- `index.ts` 只剩门面与公开 API，`queue.ts` 不认识 HTTP，`ownership.ts` 不认识命令，`http.ts` 不认识端口选举。
- 公开 API、协议、超时数值全不变；`test/bridge/` 一行没改。
- 测试没有新增注入点。真要测抢端口的失败分支，得先有一个可注入的 `fetch`，那是给未来加 API，不做。

## 砍了什么

- 没拆出 `version.ts`：版本闸只有两处赋值，一个字段比一个模块便宜。
- 没改端点、没换 HTTP 框架、没动长轮询。
